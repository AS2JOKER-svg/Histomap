# HistoMap — contexte pour l'agent

## Le produit
Site éducatif d'histoire en français (public : 13 ans et +), mobile d'abord, installable (PWA), 100 % statique (aucun serveur, aucune API, aucune clé). Objectif : publication commerciale (Play Store, KnightBorn Studio) → le contenu doit être **irréprochable**.
Trois espaces :
- **Frise** : époques → continents → civilisations (fiches).
- **Carte du monde** : 54 cartes historiques datées, curseur temporel, clic sur un territoire → fiche, conflits affichés.
- **« On avance »** (révisions) : époque → civilisation → chapitre de cartes à faire glisser (niveau 1 puis niveau 2 quand on reprend) → quiz de 20 questions, validé à 15/20 ; sous 15, 5 questions ratées reviennent au quiz suivant.
La progression est sauvegardée dans le navigateur (localStorage). Vibrations sur mobile aux bonnes réponses.

## Pile technique
React 18, Vite 4, Tailwind 3 (couleurs = variables CSS, thèmes clair/sombre), framer-motion, zustand (état + persistance), react-router-dom 6 en **HashRouter** (URLs `#/frise/...`), d3-geo + topojson pour la carte.
Tout le code est dans `front/`. Commandes (depuis `front/`, ou depuis la racine : le `package.json` racine les relaie vers `front/`) :
- `npm run dev` : compile le contenu puis lance le serveur (http://localhost:5173/Histomap/)
- `npm run data` : compile le contenu + valide tout (**À LANCER APRÈS CHAQUE MODIFICATION DE CONTENU** : 0 erreur, 0 alerte)
- `npm run validate` : valide seulement (+ tests de l'Aventure)
- `npm test` : tests des règles de l'Aventure (parcours, XP, niveaux, validateur)
- `npm run coverage` : rapport de couverture (région × siècle, territoires des cartes sans fiche) → `front/reports/couverture.md`
- `npm run links` : vérifie que tous les liens Wikipédia de `content/` mènent à une page existante (réseau requis ; à lancer après chaque lot de fiches)
- `npm run eclairs` : rapport des questions éclair (questions rattachées à une carte, posées en Découvrir et Approfondir, salle par salle) → `front/reports/questions-eclair.md`
- `npm run territoires -- <mot> [<mot>…]` : cherche des noms de territoires dans les cartes historiques (années, fiche déjà reliée) pour remplir `territories`
- `npm run zone -- <année> <ouest> <sud> <est> <nord>` : liste les territoires d'une carte historique dans une zone (pour colorer les cartes des dossiers de guerre)
- `npm run build` : compile, valide puis construit `dist/` (+ service worker)
- `npm run preview` : sert le build (tester le hors-ligne ici, pas en dev)

## Où sont les choses
- **`front/content/` = la source de tout le contenu** (JSON, un fichier par unité) :
  - `epochs.json` : époques → continents → **liste ordonnée des ids** de civilisations (le plan du site) ;
  - `civs/<id>.json` : une fiche par civilisation (105 aujourd'hui) ;
  - `people/`, `events/`, `discoveries/` : fiches liées (personnes, événements, découvertes), cliquables depuis les textes ;
  - `lineages.json` (même civilisation sur plusieurs époques : couleur commune, « La suite »), `regions.json` (régions actuelles normalisées), `conflicts.json` (lieu des guerres sur la carte), `ignore-territories.json` (territoires des cartes volontairement sans fiche) ;
  - `parcours.json` : **parcours de l'Aventure** (V3 : tronc de chaque monde, branches → parent, titres) ; format dans GUIDE_EDITION.md ;
  - `wars/<id>.json` : **dossiers de guerre** (page `/guerres/<id>` : phases, carte animée, batailles, personnages, quiz) ; format dans GUIDE_EDITION.md.
- `front/scripts/build-content.mjs` compile `content/` → `front/src/data/` (**généré, ignoré par git, ne jamais éditer**) : `index.json` (index léger chargé au démarrage), `civs/<id>.json` (détail chargé à la demande), `entities/`, `territories.json`, `conflicts.json`, `quiz-context.json`, `map-presence.json`. `scripts/lib/content.mjs` = lecture/assemblage partagés ; `scripts/lib/json.mjs` = écriture JSON lisible pour `content/`.
- `front/scripts/validate-content.mjs` (contenu) et `validate-revision.mjs` (chapitres) : lancés par `data` et `build`.
- `front/public/map/` : cartes historiques (projet historical-basemaps, **licence GPL-3.0**, garder LICENSE et NOTICE.md). `src/data/map-years.json` : généré par `npm run map` (rare), versionné.
- `front/src/data/revision/<id>.js` : **un chapitre de révision par civilisation** (cartes + quiz + bilan). `index.js` et `revision-meta.json` sont **générés** par `scripts/build-revision-index.mjs`.
- `front/src/lib/` : `data.js` (index léger : getEpochs, getCivilization… ; détail : `loadCiv(id)` / `useCiv(id)`), `links.js` (syntaxe des liens `[[id|texte]]`), `revision.js`, `chapters.js`, `quiz.js`, `questions.js` (affichage/correction d'une question, léger), `random.js` (hasard reproductible, aussi utilisé par les scripts), `map.js`, `color.js`, `storage.js`, `haptics.js` (vibrations + sons d'interface), `pwa.js` ; depuis le sprint 25 : `sons.js` (sons d'interface synthétisés en Web Audio, clé `histomap_sons`), `musique.js` (musique d'ambiance par région, générée en Web Audio, désactivée par défaut, clé `histomap_musique` ; `useAmbiance(civId)` dans les pages), `defi.js` (défis sans serveur : même graine = mêmes 10 questions, lien `#/defi/<civ>?g=&s=&n=`) ; depuis le sprint 26 : `eclairs.js` (questions éclair sur les cartes déjà lues : rattachement question → carte par rapprochement de texte, en attendant le champ `carte` du sprint 28), `useDelai.js` (verrou anti double toucher), réglage `histomap_vibrations` dans `haptics.js`.
- Quiz express des fiches liées : généré au build par `front/scripts/lib/express.mjs` (champ `express` de `src/data/entities/<id>.json`), joué par `src/components/quiz/ExpressQuiz.jsx`. Règle : une seule bonne réponse possible (leurres d'autres continents/familles, question écartée si la réponse se lit dans le nom, dates en siècles exclues des questions de date et d'ordre).
- `front/src/store/` : `progress.js` (progression, clé `histomap_progress`, version 3 : + `express` (v2), + `aventure` (v3, logique pure dans `src/lib/progression.js`, migration v2 → v3 `migrerV2`)), `ui.js`, `app.js`, `audio.js` (sons et musique activés).
- `front/src/pages/` : une page par écran. `front/src/components/` : composants (ui/ = briques de base, dont `RichText` pour les textes à liens ; fiche/ = briques communes des fiches ; `RefSheet` = aperçu d'une fiche ouvert de partout via `useUI().openSheet`).
- Barre du bas (V3) : **Aventure** (`/`), **Atlas** (`/atlas` → dernière vue : `/frise…` ou `/carte`, bascule `AtlasSwitch`), **Guerres**, **Profil** (`/profil`) ; recherche et bouton musique dans l'en-tête ; bouton « Défis » dans l'en-tête de l'Aventure.
- Routes : `/` Aventure (`?monde=<époque>`), `/atlas`, `/profil`, `/frise…`, `/frise/:epoque/:civ?onglet=…` (fiche à 6 onglets), `/fiche/:id` (fiche liée), `/carte`, `/guerres`, `/guerres/:id` (dossier de guerre), `/recherche`, `/bienvenue` (premier lancement), `/aventure/mondes`, `/aventure/salle/:civ/:etape` (decouvrir | approfondir | epreuve), `/aventure/a-revoir/:civ` (séance « À revoir »), `/defis` (défis), `/defi/:civ` (défi par lien ; `?g=<graine>&s=<score>&n=<prénom>` = défi reçu), `/defis/a-deux` (à deux sur le même téléphone), `/entrainement` (quiz infini) ; anciens liens redirigés : `/reviser` et `/reviser/:epoque` → Aventure, `/reviser/:epoque/:civ` → Découvrir ou Approfondir, `…/quiz` → Épreuve.
- `front/GUIDE_EDITION.md` : **formats détaillés du contenu** (à lire avant d'écrire une fiche ou un chapitre).

## Formats de contenu (résumé — détail dans GUIDE_EDITION.md)
- **Fiche de civilisation** `content/civs/<id>.json` : id (= nom du fichier), label, tier (1 majeure, 2 secondaire, 3 mineure), region (id de `regions.json`), period, start, end (années, négatives av. J.-C.), color (absente si la civilisation est dans une lignée), trackId/row (piste sur la frise), isRiver, capitale, description, territories, datesCles [{annee, evenement, info, ref?}], dirigeants [{nom, titre, debut, fin, surnom?, dynastie?, personne?}], dynasties? [{id, nom, debut, fin}], personnages [{nom, role, description, dates, wikiUrl, ref?}], guerres [{nom, annee, adversaires[], allies[], morts, vainqueur, consequences, wikiUrl}], sciences, croyancesText, diplomatie, documentaires [{titre, url}], sources? [urls]. Champ inconnu = erreur.
- **Ajouter une civilisation** = créer `content/civs/<id>.json` + ajouter son id dans `content/epochs.json` (continent voulu, à la place voulue) + la placer dans `content/parcours.json` (tronc ou branche).
- **Fiches liées** : `content/people/<id>.json` {id, nom, description, role?, dates?, naissance?, mort?, wikiUrl?, sources?} ; `events/` {id, nom, annee, description, fin?, lieu?…} ; `discoveries/` {id, nom, description, annee?, domaine?…}. Les ids sont uniques dans tout le site (civilisations comprises).
- **Liens dans les textes** : `[[id]]` (affiche le nom de la fiche) ou `[[id|texte affiché]]`, dans n'importe quel texte de `content/`. Un lien vers une fiche inexistante bloque le build.
- **Chapitre** `src/data/revision/<id>.js` : modèle = `carthage.js`. ≈ 9 cartes tier 1 + 5 tier 2 ; types : text, keyfigure, dates, steps, map, war, person, leaders ; quiz 15-18 questions (mcq : bonne réponse en position 0, mélangées à l'affichage ; tf ; order : éléments dans le bon ordre) ; recap : 4 lignes. Carte `map` : années prises UNIQUEMENT dans `src/data/map-presence.json` pour cette civilisation.
- Les `id` de questions et de cartes ne doivent jamais être renommés (ils servent à mémoriser la progression).

## Règles à respecter
1. Après toute modification de contenu : `npm run data` doit afficher 0 erreur et 0 alerte. Après toute modification de code : `npm run build` doit passer.
2. **Exactitude historique d'abord** : faits consensuels, dates prudentes (« vers », « selon la tradition »), ton neutre sur les sujets sensibles, pas d'anachronisme. Ne jamais inventer un chiffre ou un nom. Sources : liens Wikipédia (ou mieux) dans `sources` ; ne jamais **recopier** un texte de Wikipédia (licence CC BY-SA, incompatible avec une app commerciale fermée) : reformuler.
3. **Un fichier par unité de contenu**, et ne jamais éditer les fichiers générés (`src/data/` sauf `revision/<id>.js` et `map-years.json`).
4. **Rédiger puis relire** : après avoir écrit un lot de contenu, faire une passe de relecture factuelle séparée et lister les corrections.
5. Couleurs : utiliser les classes de thème (`text-ink`, `text-muted`, `bg-surface`…, et depuis la V3 `bg-accentbtn` pour un fond sous texte blanc, `text-gold`/`bg-gold` pour l'or sur encre), jamais `bg-white`/`text-gray-500`. Thème V3 « Musée vivant » (`src/index.css`) : papier crème, encre, terre cuite, or ; titres Cormorant Garamond, texte DM Sans. Couleur d'une civilisation en texte : `className="civ-text" style={civTextStyle(color)}` ; fond sous texte blanc : `solidBg(color)` (`src/lib/color.js`). Accessibilité : contraste AA, boutons ≥ 44 px, `aria-label` sur les boutons-icônes.
6. `localStorage` : toujours via `src/lib/storage.js`. Si la forme de `histomap_progress` change : incrémenter `VERSION` et compléter `migrate()` dans `store/progress.js`.
7. Garder les anciens liens (`#/frise/...`, `#/carte`, `#/reviser/...`) fonctionnels.
8. Ne pas ajouter de serveur, de compte utilisateur ni de pistage.
9. Petits pas : à la fin de chaque sprint, **un commit** (branche de travail, jamais de push sans accord) et un résumé : ce qui a été fait, vérifié, et ce qui reste douteux. Les sprints dont le but est une validation (liste d'une vague, pilote) attendent la réponse de l'utilisateur.
10. Refonte des données ou du code de calcul : comparer avant/après ce que l'app produit (questions de quiz, cartes de révision, conflits, territoires) — aucune différence non voulue.

## V3.1 « Allègement » (cadrage du 16/11/2026)

**Méthode** : un sprint = une conversation. Au début d'un sprint : lire cette section en entier, puis le sprint visé. À la fin : passer le sprint en ✅ ici avec un résumé court (fait, vérifié, douteux) et faire un commit sur `v3-1`. Exception : le sprint 26 est fusionné dans `main` et poussé dès qu'il est fini (les testeurs jouent sur le site). Le sprint 27 (maquettes) **attend la validation de l'utilisateur** avant tout code des sprints 30 à 32. Ce qui n'est pas tranché ici se tranche sur les maquettes, pas en codant.

### Retours des testeurs (3.0) et diagnostic
- **Pas de vibrations** : le téléphone était en mode silencieux ; Chrome sur Android n'exécute pas `navigator.vibrate` en silencieux (impossible à corriger sans app native : choix assumé, on reste PWA/TWA). En plus, `src/lib/haptics.js` coupe les vibrations si « réduire les animations » est actif, et les motifs très courts (8-14 ms) se sentent mal.
- **Questions sur des cartes pas encore vues** : les questions éclair (`Etape` dans `src/pages/SallePage.jsx`) sont tirées de toutes les questions rédigées du chapitre ; celle du milieu du paquet peut porter sur la seconde moitié ; l'Épreuve ajoute ≈ 6 questions générées depuis la fiche complète. Aucune question n'est reliée à une carte.
- **Question sautée (on passe de 1 à 3)**, en Épreuve et en questions éclair : pas encore reproduite. Pistes : double toucher sur « Question suivante » pendant l'animation de sortie (`AnimatePresence mode="wait"`) ; reprise d'une épreuve (`step = answers.length`) quand une question des `ids` a disparu du réservoir (filtrée dans `questions` alors que `finishQuiz` compte `ids.length`) ; numérotation de la question du milieu.
- **Combo bloqué à ×5** : plafond voulu (`BAREME.comboMax`), vécu comme une limite.
- **Approfondir** long et bloquant ; **annexes** aussi longues qu'une salle du tronc ; envie de passer l'Épreuve plus tôt.
- **Écran beaucoup trop chargé** (Aventure, panneau d'une salle, Profil) ; envie d'une **carte de tout le parcours** à la Candy Crush, **de bas en haut**.
- **Notifications** demandées.

### Décisions (validées le 16/11/2026)
**Une salle du tronc**
1. **Découvrir** (cartes essentielles + 3 questions éclair) = salle **découverte** → ouvre la salle suivante.
2. **Épreuve** ouverte dès que la salle est découverte ; **12 questions** (au lieu de 20), plus de mi-temps ; **★ 9/12, ★★ 11/12, ★★★ 12/12** ; réussie = au moins ★ ; ratée : 3 questions ratées reviennent à la suivante.
3. **Approfondir = bonus facultatif** (XP) qui ne bloque rien ; s'il est fait, ses cartes entrent dans le réservoir de l'Épreuve.
4. **Plus de médailles bronze/argent/or** : seulement **0 à 3 étoiles** par salle + une pastille « découverte ». Les seuils ne s'affichent qu'à l'écran de résultat.
5. **Chemin continu** : la dernière salle d'un monde, une fois découverte, ouvre le monde suivant (fin de la règle « tout le tronc en argent »). L'Épreuve n'est jamais obligatoire pour avancer.

**Annexes (branches)**
6. **Une seule séance** (≈ 4 min) : les cartes essentielles puis une **mini-épreuve de 8 questions** sur ces cartes, sans mi-temps ; ★ 6/8, ★★ 7/8, ★★★ 8/8 ; annexe faite = séance terminée. Pas d'Approfondir (ses cartes restent lisibles dans la fiche).
7. Une annexe s'ouvre quand sa salle parente est découverte (parenté de `content/parcours.json` inchangée).

**Questions**
8. **Toute question porte sur une carte déjà vue** : questions éclair = cartes déjà lues dans la séance (celle du milieu = première moitié du paquet) ; Épreuve = cartes de Découvrir (+ Approfondir s'il est fait) ; mini-épreuve d'annexe = cartes de la séance. Plus de questions générées depuis la fiche complète dans l'Aventure. Défis et entraînement : questions reliées aux cartes de la salle (Découvrir + Approfondir). Le quiz express des fiches liées ne change pas.
9. Chaque question rédigée porte l'id de sa carte (champ `carte`). Quand une salle manque de questions : d'abord des questions **générées depuis les données des cartes elles-mêmes**, puis des questions **rédigées à la main**, avec relecture séparée. Les `id` de questions ne changent jamais.

**Combo**
10. Le compteur continue au-delà de ×5 (×6… jusqu'à ×12 = sans faute), avec un effet et un son qui montent ; **l'XP reste plafonnée à ×5** ; « Combo max ! » dès ×5.

**Carte du parcours (écran Aventure)**
11. **Une seule carte verticale** de tout le parcours, **de bas (Préhistoire) en haut (fin)**, à la Candy Crush ; elle s'ouvre sur la salle en cours ; un bouton flottant « Ma salle » y ramène quand on s'en éloigne. Salle en cours = première salle du chemin pas encore découverte (ou dont une étape est commencée).
12. Chemin = salles du tronc + salles du fil rouge du joueur. **Pastilles rondes avec initiales + nom court dessous**, étoiles sous les salles faites ; salle en cours plus grosse, avec « Jouer ».
13. **Annexes = petites bulles** accrochées à leur salle parente, sur le côté du chemin.
14. **Le fil rouge entre dans le chemin** : ses civilisations qui sont des annexes deviennent des salles **obligatoires** du chemin pour ce joueur, à leur place (après leur salle parente, sinon par date de début dans leur monde ; ex. fil Corée = +5 salles, fil France = +0). À la dernière salle du fil : célébration + titre du fil, puis le chemin continue jusqu'en haut et le joueur peut choisir un autre fil. Changer de fil ne referme jamais une salle déjà ouverte ; les salles ajoutées derrière la position du joueur sont « à rattraper », sans bloquer (à confirmer sur maquette).
15. **Décor** : chaque monde a sa couleur, ses motifs et quelques **pictogrammes SVG dessinés en code** (silex, colonne, château, caravelle, usine…). Toujours **aucune image**.
16. **« À revoir »** : une **bulle** à côté de la salle en cours dès 5 erreurs ou 3 jours (une séance par jour, +20 XP, comme aujourd'hui).
17. **Plus de bandeau fixe** « À reprendre · Jouer » en bas.

**Écrans**
18. En haut de l'Aventure : **seulement la pastille de niveau + la barre d'XP**. La série (flamme) va dans le Profil ; la recherche reste dans l'Atlas ; musique, thème clair/sombre et « i » (présentation) vont dans **Réglages**. L'en-tête global ne garde que le logo (+ la recherche dans l'Atlas).
19. **Panneau d'une salle court** : nom, dates, étoiles, **un seul gros bouton** (étape suivante), une ligne d'étapes (« Découvrir ✓ · Épreuve ☆☆☆ »), « + Approfondir (bonus) », « Lire la fiche ». Plus de détail d'XP, de seuils, de liste d'annexes ni de « Défier un ami ».
20. **Profil court + sous-pages** : en haut niveau, rang, titre affiché, série, 3 chiffres (salles, étoiles, jours) ; puis 4 entrées : **Collections** (mondes, fils rouges, titres), **À revoir**, **Défis**, **Réglages**.
21. **Réglages** (depuis le Profil) : sons, musique, thème clair/sombre, vibrations (interrupteur, bouton « Tester », phrase sur le mode silencieux d'Android), notifications, revoir la présentation, à propos (licences).
22. **Défis** (par lien, à deux, quiz infini) : seulement depuis le Profil.

**Mécaniques**
23. **Retirés** : cosmétiques (thèmes d'accent dont « Indigo », sceaux, cadres, effets), **coffres**, **objectif de la semaine**. Le thème sombre « Musée de nuit » reste (Réglages).
24. **Gardés** : XP ; niveaux → **rangs** (écran de félicitation à chaque nouveau rang) + places de **joker** ; série + jokers ; **titres** = au moins ★ sur toutes les salles concernées (monde, fil rouge, titre ultime) ; combo ; partage de l'image de résultat (sans cadre ni édition dorée).

**Notifications et vibrations**
25. **On reste PWA/TWA** (pas d'app native). Notifications locales **au mieux**, via la synchronisation périodique de Chrome (Periodic Background Sync : Android, app installée ; heure non garantie, rien sur iOS) : **rappel quotidien** (si pas joué ce jour-là, à partir de l'heure choisie, 18 h par défaut) et **« série en danger »** le soir ; **2 par jour au plus**, rien entre 21 h et 8 h ; autorisation demandée **seulement dans Réglages**. Au Play Store : activer la délégation des notifications de la TWA.
26. **Vibrations** : API du navigateur (coupée par Chrome en mode silencieux, expliqué dans Réglages) ; motifs allongés ; interrupteur dédié, indépendant de « réduire les animations ».

**Sauvegarde**
27. Migration `histomap_progress` **v3 → v4** : médaille ≥ bronze → salle découverte ; meilleure note d'épreuve sur 20 → étoiles (15 → ★, 17 → ★★, 19 → ★★★) ; XP, série, jokers et titre affiché gardés ; coffres, cosmétiques et objectif retirés (thème d'accent choisi → thème par défaut).
